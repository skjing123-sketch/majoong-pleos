## 유지한 동작과 한계

- 실제 SDK 도착만 네이티브 arrival sequence를 올린다. 주차는 신선한 실제 속도·P단·UX 허용을 별도로 확인해야 한다. 데모 조작으로 Pleos 도착을 만들지 않는다.
- 목적지 주소 해석에 실패하면 이전 지역 사진이나 전국 공고를 자동 재사용하지 않는다. 사용자의 명시적인 지역 선택만 허용한다.
- 사진 넛지는 사진 decode 뒤6초 표시하며, 주행 재개·백그라운드·다른 경로·오래된 조회에서는 준비 중인 사진도 취소한다. 사진 실패는 다른 동물로 바꾸지 않고 브랜드/사진 없음으로 처리한다.
- 연락처가 없거나 가려졌으면 발신 링크를 만들지 않는다. 전화 앱만 열며 자동 발신하지 않는다.
- API는 발견 완료 상태를 제공하지 않는다. 공고의 상태는 `unknown`이며 “현재도 찾고 있음”으로 단정하지 않는다. 갱신된 조회에서 사라진 공고는 제거하지만 **발견 완료 자동 판정·즉시 삭제 기능은 미구현**이다.
- 위치는 동일 행정구역 기준이다. 목적지 반경 검색·공고와의 실제 거리·정확한 분실 지점 좌표를 제공한다고 주장하지 않는다. 최근30일, 한 페이지 최대50건/서버 최대3페이지 제한이 있다.
- 기본 내비를 전체 화면으로 둔 상태의 사진 overlay는 구현하지 않았다. 사진은 마중 화면/분할 화면 안의 넛지이고, 배경 서비스는 표준 텍스트 알림·toast를 사용한다.

## 실제 Pleos에 남은 확인

이 점검에서 Galaxy SSH 연결은 시간 초과였다. 에뮬레이터·차량 입력·새 APK 설치·실제 내비 경로 주행을 실행하지 않았다. 이전에 확인한 raw GPS 문장 수신과 분할 화면이 실제 SDK 도착 성공을 뜻하지 않는다.

제출 전 필요한 연결 증거는 실제 내비 경로 안내 시작 → 지도 매칭 이동 → 진짜 `onDestinationArrived` → 신선한 P/속도0/UX 허용 → 해당 도착 지역의 실공고 사진 decode → 내비가 보이는 상태에서 작은 넛지 표시와 연속 녹화다. 현재 이 전체 연결 시험과 ANR 재발 여부는 **미검증**이다. 실제 공고가 있는 목적지를 다시 확인하고 시험해야 하며, 공고가 없는 지역에서 사진이 나오지 않는 것은 정상 동작이다.
